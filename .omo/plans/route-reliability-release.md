# Work Plan: 다음 배포 — 경로 기록 신뢰성 개선

## Goal
정상적인 방문 좌표를 보존하고, 저장 성공이 확인된 경로만 완료로 표시한다. 사용자가 저장 전에 취소한 분석은 기록을 남기지 않는다. 이 동작을 자동 테스트와 기존 데이터 업그레이드 검증으로 보호한 뒤 배포한다.

## Request Summary
- 앞선 리뷰에서 확인한 경로 보정, 저장 실패 은폐, 취소 후 저장, 자동 테스트 부재를 다음 배포에서 해결한다.
- 계획 작성 후 사용자 지시에 따라 sol Medium 서브에이전트로 구현을 진행한다. App Store 업로드·제출은 별도 출시 단계다.

## Current Context
- 단일 iOS 앱 타깃, Tuist 프로젝트, SwiftData 저장소를 사용한다.
- `optimizePath`는 거리만으로 중간 좌표를 변경한다. A→B→A 왕복은 B가 A로 이동해 거리가 사라질 수 있다.
- 분석 화면은 `context.save()` 실패를 무시한 뒤 완료 상태로 전환한다.
- 분석 취소 플래그는 경로 재구성 직전까지만 확인한다. 서비스의 별도 AI Task는 호출 작업의 생명주기와 분리되어 있다.
- 서비스 재계산과 편집/타임라인 호출부에도 저장 오류를 무시하는 코드가 있다.
- `PhotoRecord` 좌표와 `Route.coordinatesData`가 별도로 존재한다. 보정은 파생 좌표에 적용되므로 기존 레코드 좌표로 복구할 수 있는지 실제 데이터로 확인한다.
- 현재 자동 테스트 타깃이 없다. EXIF 화면은 3,000줄 이상으로 여러 책임이 모여 있다.
- 현재 Project.swift 설정은 버전 1.0.3, 빌드 8이다. 실제 App Store 배포 이력은 미확인이다.

## In Scope
- 거리 기반 자동 좌표 이동 제거, 원본 레코드 기반 통계 계산.
- 기존 저장 경로의 잘못된 파생 좌표/거리 복구.
- 신규 분석의 명확한 실행·취소·저장·실패·완료 상태와 작업 소유권.
- 신규 저장 및 변경한 경로 재계산 호출부의 저장 오류 전파·복구.
- 순수 계산과 분석 생명주기를 검증하는 단위 테스트 타깃.
- 업그레이드/권한/EXIF 회귀 QA와 배포 체크리스트.

## Out of Scope
- EXIF 화면 전체 분리 및 전면 아키텍처 교체. 신뢰성 수정 배포 후 별도 계획으로 진행한다.
- 도로를 따라가는 실제 이동 경로 추정, 새 이상치 판별 모델, 신규 AI 기능.
- SwiftData 저장 필드 추가·삭제·타입 변경, 서버·분석 SDK 도입.
- 광고 정책, 권한, 번들 ID, 최소 지원 OS 변경.
- 이번 작업과 무관한 모든 `try?`의 일괄 교체, CI 인프라 전체 구축.
- 이 계획만으로 App Store 업로드·제출을 실행하지 않는다.

## Assumptions
- 정확한 이상치 판별에 필요한 근거가 부족하므로 이번 배포는 좌표 보존을 기본값으로 한다. 실제 GPS 오류도 자동으로 이동시키지 않는다.
- 표시 거리는 사진 위치 사이의 직선거리 합이며, 실제 도로 이동 거리와 다르다. 지도/공유에서 이를 알 수 있도록 짧은 설명을 제공한다.
- 제안 버전은 1.0.4이다. 버전·빌드 번호는 출시 시 App Store Connect 이력을 확인한 후 확정한다.
- AI 보완은 완료/취소 이후 모델을 변경하지 않도록 소유되는 작업 안에서 끝낸다. 기기 미지원·실패 시 기존 fallback을 유지한다.

- `docs/workflows.md`, 신규 `docs/releases/route-reliability-validation.md`: 실행 명령과 검증 증거.
- `Models/Route.swift`, `Models/PhotoRecord.swift`: 스키마를 바꾸지 않고 호환성을 확인한다.

## Implementation Steps

### 1. 기준선과 재현 fixture 준비
- [x] 작업 트리 변경을 확인하고 기존 변경을 보존한다. 현재 빌드 결과와 경고를 기록한다.
- [x] Tuist에 XCTest 단위 테스트 타깃과 명시적 테스트 scheme을 추가한다. 네트워크/Photos/AI 실호출 없이 실행되도록 입력과 저장 동작 주입 지점을 최소한으로 만든다.
- [x] 왕복 A→B→A, 정상 A→B→C, 중복 좌표, 0/1개 좌표, GPS 없는 사진, 저장 실패, 느린 분석 fixture를 준비한다.
- [ ] 기존 버전에서 경로·사진·사용자 편집 요약이 있는 저장소를 준비한다. 테스트용 저장소만 사용하고 실제 사용자 DB를 초기화하지 않는다.

### 2. 원본 좌표 기반 경로 계산 및 기존 기록 복구
- [x] 거리 조건만으로 좌표를 중간점으로 이동시키는 처리를 제거한다. 사진 시간순 레코드 좌표를 그대로 사용한다.
- [x] 좌표와 거리 계산을 순수 함수로 분리한다. 지도 좌표와 거리 계산이 같은 입력을 쓰도록 한다.
- [x] 기존 `coordinatesData`에 `isOptimized == true`인 경로를 식별하고 레코드 좌표로 파생 데이터만 재생성한다. 원본 좌표를 복원할 수 없는 데이터는 덮어쓰지 않는다.
- [x] 복구 과정에서 OCR/AI/지오코딩을 다시 실행하지 않고 사용자 제목·요약·사진을 보존한다. 건별 또는 제한된 묶음으로 처리해 전체 이미지 데이터를 한꺼번에 읽지 않는다.
- [x] 복구 저장 성공 전에 완료 표시를 남기지 않는다. 실패 시 오류를 기록하고 다음 실행에 재시도할 수 있게 하며, 반복 실행해도 결과가 같게 만든다.
- [x] 지도/공유에 사진 위치 사이의 직선거리 합이라는 설명을 추가한다.

### 3. 분석 취소와 저장의 일관성 보장
- [x] 분석 실행 Task를 한 곳에서 소유한다. 최초 실행·재시도·닫기·화면 이탈이 동일한 취소 경로를 사용하도록 한다.
- [x] 각 비동기 단계 전후에 취소 여부를 확인한다. 취소 오류를 일반 실패로 표시하지 않는다. 새 실행이 시작되면 이전 실행 결과는 반영하지 않는다.
- [x] 서비스가 생성하는 소유자 없는 AI Task를 제거하거나 부모가 기다리고 취소하는 구조로 바꾼다. 취소된 작업의 늦은 응답은 모델/통계를 수정하지 않는다.
- [x] SwiftData 모델과 컨텍스트 접근의 actor 경계를 정리한다. 오래 걸리는 처리에는 값 형태 입력을 사용하고 모델 변경/저장은 올바른 컨텍스트 실행 경계에서 수행한다.
- [x] 분석 중간 객체는 영속 컨텍스트에 삽입하지 않는다. 최종 취소 확인과 삽입·저장 사이에 비동기 중단 지점을 두지 않는다.
- [x] 저장 성공을 완료의 기준으로 삼는다. 저장이 이미 성공해 완료된 뒤의 닫기는 취소가 아닌 결과 화면 닫기로 처리한다.

### 4. 저장 실패와 재시도
- [x] 신규 분석의 `try? save()`를 명시적 오류 처리로 바꾸고 저장 실패 시 완료 화면을 열지 않는다.
- [x] 실패한 삽입이 autosave로 나중에 저장되지 않도록 분석 전용 컨텍스트 또는 이에 준하는 격리된 저장 경계를 사용한다. 공유 컨텍스트 전체 rollback으로 다른 편집을 취소하지 않는다.
- [x] 저장 실패 시 사용자에게 저장되지 않았음을 알리고 재시도를 제공한다. 재시도 성공 시 경로는 정확히 1개만 남는다.
- [x] 서비스의 내부 저장을 정리하고 변경한 편집/타임라인 호출부가 저장 오류를 받도록 한다. 실패한 변경이 조용히 완료로 처리되거나 나중에 자동 저장되지 않게 한다.
- [x] 원인 확인용 오류 기록에는 사진 내용·OCR 원문·좌표를 포함하지 않는다.

- [x] 테스트 명령을 `docs/workflows.md`에 반영한다. 누군가 동일 명령으로 재실행할 수 있어야 한다.
- [ ] 출시 이력 확인 후 버전·빌드 번호를 설정하고 Release archive 및 서명을 검증한다.
- [ ] 배포 담당자가 TestFlight 후보 빌드로 업그레이드 QA를 완료한 뒤 App Store 배포를 진행한다. 미검증 항목을 통과로 처리하지 않는다.

## Acceptance Criteria

체크된 항목은 아래 자동 테스트/정적 검토 범위에서 확인했다. 실제 사진과 이전 배포 버전 업그레이드는 별도 수동 검증 항목으로 남긴다.
- [x] A→B→A의 B 좌표가 유지되고 거리는 A↔B 거리의 약 2배다. 정상/중복/빈 입력도 명시된 결과를 반환한다.
- [x] 기존 보정 경로는 원본 레코드 기반으로 복구되며 사진 수·제목·사용자 편집 요약은 보존된다.
- [x] 저장 실패 시 완료 화면이 나타나지 않고, 재실행한 저장소에도 실패한 경로가 없다.
- [x] 저장 재시도 성공 후 재실행해도 경로가 정확히 1개 존재한다.
- [ ] 메타데이터/OCR/지오코딩/AI 요약/저장 직전 각각 취소하면 신규 경로가 0개다.
- [x] 닫기·재시도 이후 이전 작업의 늦은 응답이 새 실행 결과나 저장된 모델에 영향을 주지 않는다.
- [ ] 편집/타임라인의 재계산 성공·실패가 UI와 실제 저장소에서 일치한다.
- [ ] 기존 저장소 업그레이드, GPS 없음 fallback, EXIF 단일/배치 저장·공유가 통과한다.
- [ ] 자동 테스트 및 simulator build 통과, 실제 지원 기기 QA와 Release archive 검증 완료 후에만 출시한다.

## Verification Plan

### 자동 검증
```sh
tuist generate
xcodebuild -list -workspace PhotoRava.xcworkspace
xcodebuild -showdestinations -workspace PhotoRava.xcworkspace -scheme PhotoRava
xcodebuild -workspace PhotoRava.xcworkspace -scheme PhotoRava -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' -derivedDataPath /tmp/PhotoRava-build CODE_SIGNING_ALLOWED=NO build
```

아래 명령은 새 테스트 타깃을 PhotoRava scheme의 test action에 연결한 후 실행한다. `<SIMULATOR_UDID>`는 앞서 확인한 설치된 시뮬레이터 ID로 치환한다.

```sh
xcodebuild -workspace PhotoRava.xcworkspace -scheme PhotoRava -destination 'platform=iOS Simulator,id=<SIMULATOR_UDID>' -derivedDataPath /tmp/PhotoRava-test CODE_SIGNING_ALLOWED=NO test
xcodebuild -workspace PhotoRava.xcworkspace -scheme PhotoRava -configuration Release -destination 'generic/platform=iOS' -archivePath /tmp/PhotoRava-reliability.xcarchive archive
```

- 계산: 왕복·정상·반복 좌표·0/1개 좌표, 날짜순 입력과 거리 오차 허용 범위.
- 취소: 단계별 중단을 제어할 수 있는 fake 서비스로 취소 시점을 재현한다. 임의 sleep에 의존하지 않는다.
- 저장: 오류를 주입한 저장 어댑터로 UI 상태와 재시도를 검증하고, 별도의 임시 디스크 SwiftData 저장소를 다시 열어 영속 개수/중복을 확인한다.
- 업그레이드: 기존 보정 데이터 복구·미보정 데이터 유지·복구 저장 실패·재실행의 동일 결과를 검사한다.
- AI: 미지원/실패/취소 fallback과 이전 실행의 늦은 응답 무시를 fake로 검증한다. 실제 AI 품질 검증과 구분한다.

## Release Gates and Recovery
- Gate 1: 계산/취소/저장 자동 테스트 통과 전 기능 완료로 처리하지 않는다.
- Gate 2: 이전 버전 저장소 업그레이드와 실제 사진 기반 QA 통과 전 후보 빌드를 확정하지 않는다.
- Gate 3: 서명된 archive와 TestFlight QA, 버전·빌드 번호 확인 후 출시한다.
- 후보에서 데이터 누락/중복/취소 후 저장이 발견되면 배포를 보류한다. 출시 후 발견하면 추가 배포를 중단하고 수정 빌드를 준비한다.
- 저장소 삭제나 사용자 앱 재설치를 복구 수단으로 사용하지 않는다. 원본 좌표를 유지하므로 파생 데이터 복구를 반복 가능하게 한다.

## Risks / Unknowns
- 거리 보정을 제거하면 실제 GPS 튐도 그대로 보일 수 있다. 이번 배포에서는 정상 방문 지점 삭제를 막고 거리의 의미를 안내한다.
- AI 작업을 기다리도록 변경하면 분석 시간이 늘 수 있다. 기존 fallback과 취소 응답성을 함께 확인하며 완료 후 임의 수정 방식으로 되돌리지 않는다.
- 기존 파생 거리로 만든 요약 문장이 복구 거리와 다를 수 있다. 사용자 편집 문구는 보존하고, 자동 요약은 기존 비AI fallback으로 갱신할 수 있는지 구분해 검증한다. 구분 불가능하면 자동 덮어쓰기 대신 재생성 안내를 제공한다.
- 기존 저장소에서 원본 레코드 좌표가 없는 경우 복구 가능하다고 가정하지 않는다.
- 테스트 타깃 신설과 Tuist scheme 구성을 실제 생성/실행으로 확인해야 한다.
- 검토 중 git 명령이 Xcode 라이선스 동의 요구로 실패했다. 구현 시작 시 환경 상태를 다시 확인하며 이 문제를 소스 결함으로 분류하지 않는다.
- 서명 계정과 실제 출시 이력은 로컬 비공개 설정/배포 담당자 확인이 필요하다. production 광고 ID는 커밋하지 않는다.
- EXIF 대규모 분리와 CI 자동 실행은 후속 작업이다. 이번 배포로 유지보수 문제 전체가 해결됐다고 주장하지 않는다.


## Execution Status — 2026-09-30

- sol Medium 에이전트 3개가 경로 코어, 분석/편집 저장, 테스트 설정을 분담했고 별도 sol Medium 리뷰 에이전트가 검토했다.
- 구현 체크는 코드 반영 여부다. 실제 기기/출시 검증 체크와 구분한다.
- 기존 데이터 복구 테스트는 이전 보정 형태를 재현한 합성 디스크 저장소를 사용했다. 실제 이전 배포 버전에서 만든 저장소 업그레이드는 미검증이다.
- 자동 취소 테스트는 제어 가능한 작업 중단/늦은 응답을 검증한다. 실제 OCR·Photos·AI 각 단계의 기기 QA는 남아 있다.
- 추가 삭제/화면 반영 테스트에서 삭제된 PhotoRecord 접근 충돌을 재현했고, 살아 있는 레코드를 먼저 조회한 뒤 반영하도록 수정했다. 조회 실패 시 부분 변경을 막는 테스트도 추가했다.
- 수정한 경로 편집 삭제 동작도 격리된 컨텍스트와 명시적 저장 오류를 사용한다. 전체 앱의 모든 저장 코드를 일괄 변경하지 않았다.
- 버전/빌드 번호는 실제 배포 이력 미확인으로 유지했다. 서명 포함 archive는 개발 팀 미설정으로 실패했으며 서명 제외 archive는 통과했다.
- iOS 18.5 및 iOS 26.5에서 17개 단위 테스트가 각각 통과했다. 서명 제외 Release archive와 독립 코드 리뷰도 통과했다.
- 최종 테스트 결과와 출시 전 미완료 항목은 `docs/releases/route-reliability-validation.md`를 따른다.
